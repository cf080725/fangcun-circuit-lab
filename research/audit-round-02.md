# 第 2 轮审查：把资料列表改成中文学习资料中心

日期：2026-11-06。范围：资料发现、阅读路线、组合筛选、收藏与最近阅读、来源说明、本地 PDF 预览。没有修改资源原文、下载状态、板卡目录、既有 PDF 或课程链接。

## 本轮交付

| 文件 | 作用 |
| --- | --- |
| `dist/resource-library.js` | 独立资料中心、状态模型、阅读指南与详情抽屉 |
| `dist/resource-library.css` | 绿与暖白主题、清楚的字号层级、原创 SVG 资料视觉标记、响应式布局 |
| `tests/resource-library.test.mjs` | 22 项针对真实风险的回归测试 |
| `research/audit-round-02.md` | 本次发现、修改与证据记录 |

不修改 `app.js`、`index.html`、`studio.css`；由主代理集成。没有使用浏览器工具；真实页面、断点布局和原生 PDF 查看器实测由主代理完成。

## 真实数据基线

审查时读取 `dist/resources.json` 的 20 条记录和 `dist/catalog-data.js` 的 `EXTRA_RESOURCES` 45 条记录，共 65 条。计数来自 `createResourceLibraryModel(...).counts()`，没有写死在页面文案里。

| 指标 | 实测数量 | 计算口径 |
| --- | ---: | --- |
| 全部资料 | 65 | 有有效 ID、标题且去重后的记录 |
| 本地 PDF | 10 | `status === 'downloaded'`，且 `download_url` 为允许的本站 PDF 路径 |
| 在线入口 | 55 | 本次未提供本地 PDF 的记录，不推断附件已经下载 |
| 中文资料 | 29 | 元数据语言标为中文或中英 |
| 课程作者资料 | 14 | 类别以“作者”开头 |
| 厂商与官方资料 | 49 | 官方或厂商类别，排除作者与公开镜像 |
| 公开镜像译本 | 2 | 类别明确标注“镜像” |

原有 20 条记录没有 `family` 字段。新模块只对已知 `st-`、`jiangxie-`、`tietou-` 旧集合补充 STM32 检索归属；其他未知记录显示“未标注”，不再无条件把缺失系列的所有新资源标成 STM32。

## 发现、修改与验证

### R2-01：65 张资料卡缺少可执行的阅读起点

**发现。** 实现前的 `index.html` 中，`#page-library` 只有一段总引导、筛选区和 `#resourcesGrid`。`app.js` 的旧 `renderResources()` 将所有记录用同一层级连续铺开。已有 754 页中文旧译本、1136 页英文参考手册与入门课程同时出现，用户需要自行判断先读什么。旧引导还给出了“江协第 3 章”的笼统指向，没有与当前资源记录建立可追踪的章节入口。

**修改。** 新模块提供三个问题入口：第一次点灯、按键与传感器、接线与下载排错。每条路线仅选 5 条既有资料，说明三个学习步骤，并连接到已有实验或故障排查页面。默认推荐顺序优先中文入门与对应课程配套。没有新增课程章节、页码或视频时间。

**证据。** `RESOURCE_ROUTES` 保存明确的资源 ID 与顺序。测试 `learning routes reference existing resources and preserve an explicit reading order` 验证所有路线 ID 均存在，筛选结果顺序与路线一致。`reading guides reuse recorded hints and do not invent document locations` 验证详情优先复用原有 `reading_hint`，缺失提示时不编造章节或页码。

### R2-02：多词搜索会漏掉实际存在的资料，已选条件也不易回退

**发现。** 旧 `renderResources()` 对完整 JSON 执行一次连续字符串 `includes(q)`，没有关键词分词。实测搜索 `GPIO 中文` 返回 0 条，虽然有多条符合这两个条件的中文 GPIO 资料。旧界面只有分散的选择框，没有已选条件汇总、逐项移除或一键恢复全部。

**修改。** 搜索仅覆盖名称、作者、类别、语言、系列、描述、阅读提示和标签等有意义的字段。支持空格分开的关键词交集、大小写归一、`I²C / I2C` 与 `I²S / I2S` 写法归一。作者、语言、系列、来源、收藏、最近阅读和本地 PDF 可组合；所有生效条件均显示为可单独清除的标签，并提供“清除全部”。输入状态立即写入模型，渲染做短暂延迟，避免快速切换选择框时丢失刚输入的查询。

**证据。** 同一份 65 条数据：旧搜索 `GPIO 中文` 为 **0 条**，新搜索为 **6 条**。测试覆盖多词中文查询、I2C 别名、四种条件交集、单条件移除、全部重置及未知系列处理。组合 `STMicroelectronics + 中文 + STM32 + 本地 PDF` 得到 `st-01`、`st-02`、`st-03` 三份记录。

### R2-03：用户不能留下“下次读”和“刚刚打开”的入口

**发现。** 原资料页没有收藏按钮、个人资料集合或阅读历史存储。用户每次都要重新筛选同一批资料；同时不应把打开资料详情当成读完原文。

**修改。** 增加收藏与最近阅读集合。收藏只存资源 ID；最近阅读只存 ID 与实际打开时间。打开原始资料入口或预览本地 PDF 才记录最近阅读；仅查看元数据或收藏不会产生阅读记录。重复打开更新排序，历史最多保留 30 条。文案明确“不表示已经读完”，没有阅读百分比或完成徽章。浏览器存储失败时保留当前页操作，并根据真实失败状态告知用户刷新后可能丢失。

**证据。** 测试覆盖收藏持久化恢复、取消收藏后的即时计数、最近记录去重与排序、未知 ID 拒绝写入、30 条上限、损坏存储与禁止存储情形。保存对象仅包含 `version`、`favorites`、`recent`，不保存文档内容或源代码。没有发送到远程服务。

### R2-04：已有文件与在线入口只有一个跳转动作，不能在资料页阅读 PDF

**发现。** 旧卡片把本地 PDF 通过新标签打开，在线入口也直接跳转。数据实际只有 10 份本地 PDF，其余 55 条是链接，不能因为目标网址包含 `.pdf` 或“配套资料”就算作已下载。

**修改。** 卡片清楚显示“本地 PDF”或“在线入口”；只有同时满足已下载状态与合法本站路径的记录启用预览。详情抽屉提供原生 PDF iframe、新标签打开及浏览器未显示预览时的明确替代入口。页数仅在原记录提供有效整数时展示。配套网盘显示已有提取码与解压密码，仍标为原作者入口，不伪造已取得附件。

**证据。** 测试验证 10 个预览路径均存在，文件头均为 `%PDF-`，页数来自原始记录。测试另构造 `link_only + PDF URL` 和 `link_only + download_url`，两者均不会进入已下载集合。外部可执行 URL、绝对远程下载路径、目录穿越和非 PDF 扩展名都无法进入本地预览路径。

**边界。** 原生浏览器 PDF 查看器的渲染、缩放与移动设备支持需要主代理页面实测；文件存在和文件头检查不等于已经完成浏览器视觉验证。

### R2-05：资料作者、原厂与公开镜像需要不同的使用方式

**发现。** 数据已有作者课程、厂商工具、芯片手册与公开镜像四种不同来源，但旧页面没有作者与厂商分栏入口，公开镜像也不容易单独查出。两个旧译本的来源类别已被准确记录，界面应保留这个区别。

**修改。** 用“跟着课程作者学”和“到厂商与官方查原文”两个栏目组织入口，展示真实的各作者资料数量。作者和厂商筛选互不混入；公开镜像单独提供筛选入口和灰色来源标记。详情抽屉显示原始发布来源、作者、语言、适用方向、真实核验日期、已有版本信息，并保留版权说明。

**证据。** `resourceSourceKind()` 优先判断镜像，再判断作者，最后判断官方或厂商。测试验证厂商集合没有江协、铁头课程或 `st-04` 镜像；源集合数量为作者 14、官方 49、镜像 2，总和 65。

### R2-06：默认标准库路线混入 HAL 教材会误导初学者

**发现。** 初稿路线同时选入野火 HAL 教材、默认江协标准外设库路线和 Arduino LED 教程；它们都能用于学习 GPIO，但工程入口、初始化方式和函数不同，放在一条默认路线会诱导直接混用。主代理在集成审查中指出此问题。

**修改。** 默认点灯和输入路线明确标为 **STM32F103 · 标准外设库（SPL）**。点灯先选江协课程及同套配套入口，野火改用已收录的标准库资料。HAL 与 Arduino 从该默认路线移出，仍可在完整资料架中检索。已明确框架的记录在卡片、详情中显示框架标签；HAL 详情突出“独立工程”和不可直接混用的说明。没有根据未明确标注的铁头新版课程猜测其框架。

**证据。** 新增测试 `default STM32 learning routes do not mix HAL or Arduino projects into the SPL path`：两条默认路线不能含 HAL 或 Arduino 项，前两个点灯入口固定对应江协课程与配套；HAL 说明必须包含不可混用提示；铁头新版未知框架返回空分类。

### R2-07：阅读界面缺少稳定的视觉锚点与详情层次

**发现。** 旧资料卡主要是类别、标题、说明和链接，没有能够快速区分课程、手册与工具的文档视觉标记。说明与阅读提示直接堆在同级卡片中，列表扫描和深入阅读没有分工。

**修改。** 使用原创 SVG 文档封面标记课程与资料类型，来源用绿、暖棕、灰色辅助区分。列表只保留类型、标题、简介、作者、文件状态和两个主要动作；阅读目标、阅读起点、三个接线对照问题、框架边界、原始来源进入侧边详情抽屉。卡片标题桌面 18px、正文主要为 14–16px，页面正文基准 16px；使用明确按钮、键盘焦点样式和原生 dialog。列表每页 12 条，显示真实总数与当前区间。

**证据。** 根据本轮 CSS 中的前景/背景色计算，相对亮度对比度：主文字 `#19372e / #fffef9` 为 **12.78:1**，正文 `#365148 / #fffef9` 为 **8.57:1**，次级文字 `#5a6a60 / #fffef9` 为 **5.67:1**，主按钮 `#fffef9 / #256348` 为 **7.03:1**，来源标签为 **5.96:1**。这些是颜色数值检查，不代替真实设备的布局验证。SVG 为装饰标记并设置 `aria-hidden`，不伪装成原文截图或书籍封面。

## 集成契约

先加载 `resource-library.css`，并停止旧资源页面的 DOM 绑定与 `renderResources()` 调用，再挂载：

```js
import { mountResourceLibrary } from './resource-library.js';

const library = mountResourceLibrary(
  document.querySelector('#page-library'),
  [...downloadedAndOriginalResources, ...EXTRA_RESOURCES],
  {
    onNavigate(page) {
      go(page); // library 使用 glossary、faults、lab 三个现有目标
    },
    onStartExample(exampleId, context) {
      loadExample(exampleId);
      go('lab');
      // context = { resourceId: string|null, reason: string }
    }
  }
);
```

`container` 可为 DOM 元素或选择器，模块只替换该容器内部，保留父页面的显示/隐藏逻辑。`resources` 为原数组，模块不修改输入对象。两个回调可省略；省略时不展示无法完成的内部导航动作。模块没有新增或猜测外部资源 URL。

返回接口：

| 方法 | 行为 |
| --- | --- |
| `getState()` | 返回筛选、收藏、最近打开、真实计数、分页和抽屉状态的副本 |
| `setFilters(partial)` | 合并部分筛选，回到第一页 |
| `resetFilters()` | 清除全部条件，回到全部资料 |
| `openResource(id, {preview = false})` | 打开指定资料；只有真实本地 PDF 可开启预览；未知 ID 返回 false |
| `refresh(nextResources?)` | 可替换数据并重新渲染；无参数时保留当前数据 |
| `destroy()` | 关闭抽屉，移除事件处理器与当前内容，不删除用户收藏 |

筛选键：`query`、`author`、`language`、`family`、`source`、`downloaded`、`collection`、`route`。本地存储键为 `physical-lab-resource-library-v1`，与实验工程存储分开，不覆盖代码或接线。

## 本轮限制

没有新增论文、硬件条目、课程链接或资料文件。在线作者网盘仍按原记录标为入口；设备和浏览器是否支持内嵌 PDF 由真实页面验证。框架标注只对既有资料中已明确的项目建立映射，不将未知课程猜成 SPL 或 HAL。默认路线是该实验台当前 STM32F103 学习路径，其他板卡与框架保留完整检索入口。
